# 原型范围与实现边界

## 定位与本轮范围

本文记录历史交互原型，位于 `prototype/`，使用原生 HTML、CSS、JavaScript、Vite 和 Neutralinojs。正式应用现已独立实现于 `src/`；下述内容仅用于原型设计参考。页面、数据和下载结果用于讨论产品行为，不能视为真实搜索、版权判断、文件生成或最终视觉方案。

本轮保留紧凑下载工具定位，增加来源能力、链接导入、歌手作品、按平台浏览排行榜与公共推荐歌单、滚动分页、虚拟列表、批次与任务详情。按用户要求排除个人歌单、播客与个性化推荐；分类暂不加入，避免引入各平台分类体系及额外导航。保留轻量试听入口，当前示例没有音频地址。

能力核对基线为 music-service 提交 `db00405aaf61409a6ae99abdb25059ac23838615`。后端的实现和已有验收不代表全部账号、歌曲、操作系统和运行配置都支持相同能力。

## 列表与歌手

- 四类搜索：单曲、歌单、专辑、歌手。九个平台的静态能力快照集中于 `providers.js`；正式接入后由 `/providers` 替换。
- 同名歌手按平台独立成行，不推断跨平台身份，不把关键词搜索结果当完整作品目录。
- 酷我、酷狗显示完整目录；网易云显示热门歌曲最多 50 首；QQ、Jamendo显示歌曲与专辑目录；咪咕只提供歌手搜索，操作退回该来源的歌曲关键词搜索。
- 歌手的存在不表示拥有整份作品版权。歌曲分别展示可下载、下载时确认、需要登录、暂不可用、仅试听；这些状态在原型中是人工样例，不能据此判断现实曲目权限。
- 已知不可用、需要登录的歌曲不能加入队列；仅试听须显式允许保存片段。未知权限仍可提交，由未来的音源解析确认。
- 未支持的来源与需要 Cookie 的 QQ 搜索显示逐源说明，不把它们的缺席等同于“没有搜索结果”。填写 Cookie 只用于展示后续流程，不声称校验有效或自动解锁曲目。

## 滚动加载与性能边界

- 界面常驻“搜索”“排行榜”“推荐歌单”三个入口。排行榜与推荐歌单按具体平台浏览：kw、wyy、qq、kg、mg、jm 支持两项；qqyy 只有推荐；5s、bl 不支持两项。点击栏目时，当前来源为“全部来源”或不支持该栏目，则自动切到第一个支持的平台 kw。手动切换平台保留受支持的栏目，不支持时返回搜索，并清空上下文、勾选和旧分页请求。推荐仍是公共歌单，不涉及个性化推荐；目录不受关键词和搜索 Cookie 门槛影响。
- 两类目录及详情复用同一分页、虚拟窗口与批量队列。榜单曲目保留顺序并显示连续名次；返回目录后可切换栏目。每个支持平台提供 64 个榜单、126 个公共歌单的虚构分页样例，数量、标题和顺序不代表平台真实目录；仅用于交互与性能验证。正式接入分别使用 `/api/v1/charts`、`/api/v1/charts/detail`、`/api/v1/charts/tracks`、`/api/v1/recommendations/playlists` 和歌单曲目接口；榜单目录若由服务一次返回，客户端仍需虚拟渲染。

- `PagedResults` 每页 50 项，接近已加载列表底部时加载下一页；同时保留可键盘访问的加载按钮。请求在执行中不会重复发送。
- 更换关键词、类型、来源或作品上下文时取消旧请求，并用请求实例隔离迟到结果；失败保留已加载内容，重试原页。
- 进入歌单、榜单、歌手及专辑时保存父列表快照；返回逐层恢复平台、栏目、查询、已加载页、勾选、滚动位置和入口焦点，不重新从第一页开始。最多保留 12 层；新搜索、切换平台／栏目或更新凭证时清理旧路径。未完成的子页请求不会污染恢复后的列表。
- 音乐列表与下载任务各自保存滚动位置，打开设置再关闭会回到原页面。重复点击当前栏目不会重置列表。具体平台不支持的搜索类型禁用，切换平台时自动回到支持的单曲搜索。
- 结果行固定 64 px，下载任务固定 80 px；仅渲染视口附近的行，两侧各预留 5 行。上下占位空间维持原滚动位置。所有响应式断点保持相同行高。
- 滚动事件经 `requestAnimationFrame` 合并，仅窗口范围变化时更新列表子树；搜索过滤在查询变化时执行，任务索引在任务变化时重建。
- 页面追加及视口尺寸变化后重新检查加载阈值；一页不足以填满视口时继续加载，不要求再滚动一次。请求中的重复触发仍被合并，失败时等待显式重试。
- 勾选以实体 ID 保存在独立 Map 中，虚拟行移出 DOM 后不丢失。全选明确为“选择已加载”，加载新页不自动扩大勾选范围。
- 全选仅保留表头入口，批量栏下载勾选项；进入歌单／歌手歌曲后可以下载整个列表。集合曲目由本地样例提供，正式接入必须逐页遍历后分批提交。
- 任务进度存储节流至约 1.8 秒；交互提交和页面离开时保存，滚动不触发存储。
- 长列表样例：搜索“林间集”，酷我 1,200 首、酷狗 420 首、网易云热门 50 首。它们是虚构压力样例，不是平台目录统计。当前样例整体常驻内存，真实接入还需设计缓存上限和分页回收。
- 自动测试验证 100,000 行下的虚拟窗口边界和有界行数，不将数学窗口测试等同于 100,000 行真实浏览器性能验收。浏览器已核对 1,200 首场景滚动到第二页后仅渲染 20 行（视口 543 px）。没有承诺所有机器的帧率或零卡顿。
- 本轮浏览器复验：公共歌单加载 100 项时渲染 21 行（视口 597 px），直接点击进入详情并返回，滚动位置保持 2,411 px，勾选与入口焦点保留。通过独立嵌入预览检查 360 px 窗口：顶部导航在窄屏分行，避免文字竖排与控件超宽；固定行高不变。

来源切换并入已有工具栏：搜索页与搜索类型同排，排行榜、推荐歌单及其详情与标题／返回同排；不再单独占一整行。单一来源列表不重复显示来源徽标，混合来源结果和下载任务保留区分。任务标题进入详情，底部服务与目标仅显示状态；重复详情入口、重复全选和未接入的验证按钮已移除。

布局统一使用响应式左右留白（24 / 20 / 12 px）与 36 px 主操作控件；搜索框 40 px，列表工具栏 52 px。窄屏批量栏优先同排，空间不足再换行；设置说明使用 11 px 字号并允许换行。列表行仍为 64 px，下载任务仍为 80 px，保持虚拟滚动计算一致。

## 下载、批次与结果

`queue.js` 为模拟队列，不请求媒体也不写文件。每次批量加入先确认数量和当前偏好，最多 100 首一批，批次之间异步让出主线程；对重复、不可用和容量不足分别计数。停止或关闭加入对话框后不再提交后续批次，已经加入的任务保留，可在下载页按批次取消。

原型活动上限为 500、历史与任务总上限为 2,000，超限明确报告未加入数量，不隐式无限排队。正式实现使用 `/limits` 额度，后台持有任务，前端关闭后任务仍可继续。

任务经过 queued、resolving、probing、downloading、processing、finalizing。取消排队项立即生效，活动项先进入 canceling；finalizing 不再接受取消。失败与取消后按原设置重试会创建新任务并保留原记录；“按当前偏好重新下载”使用当前设置，二者不混用。

“暂停开始新任务”只关闭领取新任务，不暂停正在执行的下载。正式接入此控制需要 `admin` 权限；普通用户应隐藏它或说明权限。并发由服务配置决定，原型固定三个工作位，删除了原先立即修改 1–8 并发的控件。

详情显示请求／实际音质、目标、错误、降级及试听警告、重试关系和完成产物摘要。展示的文件名、大小和处理结果同样为模拟，不提供虚假的打开文件按钮。删除记录仅作用于本地原型历史，不删除音乐文件，也不调用后台删除接口；正式实现需分离界面隐藏与服务端结果复用。

下载页支持每行复选框、Shift 连选、当前筛选列表全选（Ctrl/Cmd+A）、Delete 打开删除确认。切换状态或批次清理勾选；虚拟滚动不丢失勾选，任务离开当前筛选后自动移除其勾选。右键或“更多”打开同一个菜单：右键已选项操作整组，右键未选项改为单选。支持方向键、Home/End、Escape、Shift+F10；滚动、缩放窗口及点击外部关闭菜单。

菜单按状态提供详情、取消、按原设置重试、按当前偏好重新下载、删除记录；批量栏提供取消、重试和删除记录。菜单打开后不重排操作项，但会重新判断是否可用，执行时再次检查状态。保存文件／取消中的任务不可再次取消；运行中的任务不允许直接删除记录，必须先取消。删除需确认，仅影响已结束记录；批量重试每 20 项让出执行时间，并反馈重复、不可用、状态变化与容量限制的跳过数量。

后台当前只提供取消／重试及全局领取策略，没有单任务暂停／继续或任务记录删除路由。因此没有添加虚假的单任务暂停入口；“暂停开始新任务”仍仅影响领取排队任务，不会冻结正在下载的任务。

## 设置、凭证与服务

- “最高可用”是客户端偏好，原型映射到来源最高档并允许降级；HTTP 接口只能接收 standard/high/lossless/hires。
- 下载目标使用示例 destination_id，不再允许任意路径。目录布局、命名、独立歌词／封面导出留在服务配置，单任务只选择元数据处理策略。
- 网易云、QQ、Bilibili支持 Cookie profile 与校验；咪咕只有取流 Cookie，未实现校验。酷我、5sing不再显示 Cookie 输入。
- 每个来源暂存一份 Cookie，相当于本轮的默认凭证。多账号列表、真正的默认凭证选择、持久保存、验证与撤销接口尚未接入。
- Cookie 仅做格式检查并留在内存，不写 localStorage、Neutralino.storage、任务快照或 HTML 属性；重新打开编辑器不回显秘密。未接入的验证入口隐藏，已填写的凭证仍明确标为未验证。
- 服务地址是普通偏好；访问凭证单独留在内存。服务连接面板目前仅保存配置，不发出网络请求、不显示虚假在线状态。
- 原型继续使用 `shiyin.*.v1` / `*_v1` 存储键。读取旧偏好时丢弃任意路径和并发字段，旧 paused／活动任务恢复为 queued。当前重启恢复只是本地交互模拟，不能代替后端任务查询。

## 链接样例与正式接入

链接输入接受分享文本并抽取 HTTP(S) URL。本地仅解析明确登记的样例，未知链接提示无法读取，不自动打开或发送到外部站点：

- `https://www.kuwo.cn/play_detail/228908`：单曲样例。
- `https://www.kuwo.cn/playlist_detail/2234580349`：歌单样例。
- `https://www.kuwo.cn/album_detail/chopin`：虚构的专辑链接，仅用于本地交互。
- `https://www.kuwo.cn/playlist_detail/forest`：虚构的 1,200 首压力样例，只用于本地交互。
- `https://www.bilibili.com/video/BV1Mq4y1U7Lw/?p=1`：视频音轨交互样例，内部 cid-demo 是占位身份，不能发送真实后端。

正式实现以[后端 API 契约](https://github.com/ddmoyu/music-service/blob/main/docs/design/cpp20-refactor/backend-service/api-contract.md)及注册路由为准：连接与权限发现、游标分页、Idempotency-Key、批次提交、任务 HTTP 回读、SSE 重连同步、文件票据、凭证默认选择及错误处理均需接入。Bilibili 必须从详情获取真实 cid 后提交，不能把页码别名直接加入后台队列。跨平台匹配、自动换源、扫码登录、本地停服 NCM 导入不在本轮范围。

## 交互动效

使用原生 CSS 与 Web Animations，不增加动画依赖。悬停、勾选背景和控件边框使用约 120 ms 过渡，列表切换约 160 ms、最多移动 2 px，弹窗与抽屉约 180 ms。首屏数据返回后才播放一次内容过渡；追加分页、虚拟行回收、输入及任务进度更新不会重复触发列表动效。快速切换取消旧过渡，系统开启减少动态效果时停止当前与待播放动效，保留即时状态反馈。

## 验证

`pnpm check` 运行格式检查、Vitest 与 Vite 构建。测试覆盖虚拟窗口上界、迟到请求隔离、分页失败重试、来源身份、跨页勾选、歌手目录范围、链接错误、批量容量、任务取消／重试、秘密不持久化、DOM 焦点和动效稳定性。浏览器还需检查歌手列表、作品权限、长列表加载和任务／设置布局。没有进行真实服务联调或跨平台桌面验收。
